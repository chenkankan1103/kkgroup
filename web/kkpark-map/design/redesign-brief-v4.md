# 概念書 — Redesign Brief v4

> 老闆最終硬需求六元素：①KCD 式檢定滲透一切（每個決定被數值影響）②地圖勢力消長（園區 vs 巡查方此消彼長）③跳槽雙面④紙娃娃主角（paperdoll API 現成）⑤Cookie Clicker 式放置點擊⑥引擎不限（Blender MCP 可驅動）。
> 前三輪結晶不浪費：v1 審訊桌（雙面＝操作）、v2 多開結構（左放置右審查）、v3 沉浸層（房間/diegetic/minigame）——v4 三概念各自吸收不同結晶。
> 每概念一頁。結尾推薦排序。

---

## 概念一「街區棋王」— 勢力棋盤 × 紙娃娃走街 × 點擊據點 × 檢定對話

**Pitch 一句**：微縮 Mount & Blade——你是雙面棋手，在真實城市街區上用「人、錢、哨點」三種棋子跟巡查方搶地盤，你的紙娃娃親自在街上走每一步。

**參考組合式**：Mount & Blade 微縮（地圖勢力消長）× 楓之谷紙娃娃第三人稱走動 × Cookie Clicker（據點放置）× KCD 檢定（對話/行動全檢定）× Reigns 擺錘（雙面忠誠）。

**核心循環（玩家的一天）**：開局看街區地圖（格子化街廓，每格有歸屬色與產出）→ 派棋子（成員/哨點/資金）擴地盤或防守 → 親自走街：紙娃娃走到目標格，觸發檢定事件（說服店家＝口才檢定、搬家當＝腿力＋翻窗 minigame、被盤查＝話術檢定）→ 地盤色塊消長，收產出 → 夜里雙面通話（檢定圓謊）→ 日結：勢力圖更新，明天的街區變了樣。

**六元素對接表**：

| 元素 | 在本概念 | 放哪 |
|---|---|---|
| ①檢定滲透 | 走街每個互動都擲檢定（口才/腿力/運氣三屬性＋裝備修正）；檢定結果即時回饋（成功=格子變色+小人動畫） | 走街互動層 |
| ②勢力消長 | 街廓格子的歸屬色塊隨每日結算流動；巡查哨像燈塔把周圍格「洗藍」，你的場所「染綠」——**地圖本身就是戰場 UI** | 全屏地圖 |
| ③跳槽 | 中期巡查方發出招募：接受＝你的棋子全部變敵方單位，目標反轉為「清空自己的綠格」——已鋪的每個據點都變成要拆的牆 | 劇本分岔層 |
| ④紙娃娃 | 第三人稱紙娃娃走街（現有 Leaflet+marker 技術全回收）；來訪 NPC 也用紙娃娃 | 主角＋NPC |
| ⑤放置點擊 | 每個綠格是點擊產出機（點擊催收＋離線自動產）；巡查格會「偷」你的產出——放置與勢力直接掛鉤 | 據點互動層 |
| ⑥引擎 | PixiJS 2D 格子地圖＋paperdoll sprite（CDN 現成圖）；地圖格子用真實街廓切分 | — |

**技術選型**：PixiJS（格子渲染 60fps 輕鬆）＋paperdoll API 拿 sprite＋現有深色瓦片當底圖。工作量：**12–16 人日**。風險：格子化街廓的「真實城市感」要設計好，否則退化成普通 board game；檢定數值表要早定。

**跳槽翻轉的樣子**：棋盤不換，陣營換——你前期花 10 小時鋪的每一個綠格，變成你後期要一格格「洗藍」的目標；老部下會來求情（檢定放水=信任損、不放=完成度）——**前期放置的每一格都是後期劇情的彈藥**。

## 概念二「我的房間，兩座城」— 第一人稱房間 × 螢幕內勢力地圖 × 桌面 minigame × 檢定會議

**Pitch 一句**：v3 房間完全體——你坐在房間裡，左螢幕是園區放置（Cookie Clicker 隔著螢幕），右螢幕是勢力地圖（消長即時演），真人來訪坐你對面，每次會面是檢定會議。

**參考組合式**：KCD 第一人稱沉浸 × Papers Please（桌面作業）× 多開大佬（螢幕內多系統）× Reigns（會面檢定）× Slay the Spire（檢定樹）。

**核心循環（玩家的一天）**：窗光開機 → 左螢幕收放置產出＋派單（點擊爽在螢幕內）→ 右螢幕看勢力消長（夜間巡查洗掉你兩格＝今天要處理）→ 處理桌面暗件（v3 minigame：蓋章/描簽名）→ 電話/來訪：檢定會議（口徑賬本翻舊帳）→ 日結擺錘 → 離線＝房間留痕。

**六元素對接表**：

| 元素 | 在本概念 | 放哪 |
|---|---|---|
| ①檢定滲透 | 會議對話全檢定（三屬性＋當天狀態修正：睡飽/咖啡/受傷）；minigame 也有隱性檢定（手穩度） | 對話層＋minigame |
| ②勢力消長 | 右螢幕的戰況地圖（等距 2.5D 街區，色塊流動+小紙娃娃單位在街上互撞——**螢幕中的戰場**） | 右螢幕 |
| ③跳槽 | 第三幕：巡查局長親自來訪（第一次走出辦公桌跟你面對面），檢定成功=調職令發放 | 劇情層 |
| ④紙娃娃 | 對面坐的來訪者全紙娃娃；右螢幕戰場單位用迷你紙娃娃（同一 API 兩種尺寸） | 對面＋螢幕內 |
| ⑤放置點擊 | 左螢幕園區後台：格網點擊+離線產出（v2 左帳原樣） | 左螢幕 |
| ⑥引擎 | DOM 房間＋兩個 canvas 螢幕（勢力地圖用 PixiJS 等距渲染）；Blender MCP 可產「房間道具」渲染圖當桌擺素材（一次性，非即時 3D） | — |

**技術選型**：DOM+PixiJS 混合；Blender 只做素材烘焙（桌子、擺設、道具的高質感 render→sprite），不做即時 3D。工作量：**16–22 人日**。風險：工程最重；兩個螢幕的資訊密度要控制（一眼讀不完=挫敗）。

**跳槽翻轉的樣子**：調職後**房間換成巡查局辦公室**（同引擎新場景：桌上的東西全換——舊房間的每件裝備都有「沒收版」對應物），左螢幕變監聽台（聽園區），右螢幕是同一張勢力地圖（但你在藍色那邊看）——**同一個房間引擎跑兩段人生**。

## 概念三「臥底人生」— 放置時間軸 × 屬性成長 × 檢定人生事件 × 跳槽結局樹

**Pitch 一句**：BitLife/放置人生——時間軸自動流轉，你的紙娃娃從雜魚爬到雙面大位，每個人生節點是一次檢定，放置產屬性、檢定花屬性。

**參考組合式**：BitLife（時間軸人生）× Cookie Clicker（屬性放置）× KCD 檢定（事件擲骰）× Reigns（事件卡連鎖）× 楓之谷紙娃娃（成長可視）。

**核心循環（玩家的一天）**：時間軸自動推進（1 真實分=1 遊戲日）→ 事件卡上桌（檢定或花屬性改寫結果）→ 點擊「修練」分配放置產出（口才/腿力/運氣/膽量）→ 勢力消長以頭條形式流過（你派的人贏了/輸了改變街區明暗）→ 階段 boss 事件（審計/盤查/招攬）= 連環檢定。

**六元素對接表**：

| 元素 | 在本概念 | 放哪 |
|---|---|---|
| ①檢定滲透 | 一切事件檢定（屬性+裝備+當日運勢）；檢定歷史留檔（你的人生日記） | 事件層 |
| ②勢力消長 | 街區明暗度條（抽象但可見，頭條文案+小地圖閃爍）——最輕實作 | 頭條+迷你地圖 |
| ③跳槽 | 結局樹：5 種結局（雙面大位/投警/雙輸/金蟬脫殼/被滅口），由跳槽時機+屬性+把柄數決定 | 結局層 |
| ④紙娃娃 | 紙娃娃隨劇情換裝（雜魚→主管→線人→警官各套穿搭——paperdoll API 天生支持換裝） | 主角成長可視 |
| ⑤放置點擊 | 屬性修練點擊（手動點=快、離線=慢，經典 Cookie Clicker 曲線）+下線派遣自動跑 | 修練層 |
| ⑥引擎 | 純 DOM（最輕）；紙娃娃換裝是現成 API | — |

**技術選型**：純 DOM+CSS，零 canvas。工作量：**8–12 人日**。風險：**角色感最弱**（老闆磚③自知）——紙娃娃只是頭像不是身體；事件文案池要深，否則第三天膩（前科：POI 事件池）。

**跳槽翻轉的樣子**：時間軸一分為二——跳槽後頭條換主編、檢定表換對手、**你培養的每個下屬變成要處理的對象**（檢定：策反/清洗/放走）。

## 推薦排序

| # | 概念 | 理由 |
|---|---|---|
| **1** | **概念一「街區棋王」** | 唯一同時把②勢力消長做成**主玩法**（不是 UI 裝飾）且紙娃娃「身體在場」的概念——六元素全部正面命中、無一妥協；Mount & Blade 式「地圖即戰場」與放置點擊天然互餵（地盤=放置機）；工作量居中，回收最多（Leaflet/瓦片/marker/派遣概念全接得上） |
| 2 | 概念二「兩座城」 | 沉浸感最深（v3 結晶完全體），但工程最重且②勢力消長隔著螢幕——「地圖是看的不是踩的」，元素②的體感打折 |
| 3 | 概念三「臥底人生」 | 最快出貨、六元素齊但都淺——適合當**先導試做**（2 週內驗證檢定手感的prototype），但撐不起「大遊戲感」 |

**一句話推薦**：主推概念一；概念三可當它的檢定系統 prototype 先行驗證；概念二的角色感精華（來訪對坐）已被概念一的走街互動吸收。六元素逐項：①概念一走街檢定②格色消長即主玩法③棋盤反轉④紙娃娃走街⑤綠格點擊放置⑥PixiJS+sprite 路線成熟。
